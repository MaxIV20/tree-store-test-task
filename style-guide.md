# Frontend style guide

Руководство по архитектуре и правилам разработки Vue 3 SPA.

---

## Структура приложения

```text
src/
├── app/                    # запуск, провайдеры, роутер и глобальная оболочка
├── pages/                  # тонкие компоненты маршрутов
├── layouts/                # повторно используемые каркасы страниц
├── widgets/                # крупные законченные блоки интерфейса
├── features/               # самостоятельные действия пользователя
├── entities/               # предметные данные, серверное состояние и доменная логика
├── shared/                 # переиспользуемый код без связи с доменом
└── utils/                  # только глобальная техническая инфраструктура
```

Проект использует FSD с плоскими слайсами. Код другого слайса доступен только
через его корневой публичный `index.ts`.

| Слой | Ответственность |
| --- | --- |
| `app` | Собирает приложение, подключает роутер, провайдеры и глобальную инфраструктуру. |
| `pages` | Композирует конкретный маршрут без бизнес-логики. |
| `layouts` | Задаёт повторно используемый каркас нескольких страниц. |
| `widgets` | Формирует законченный функциональный блок интерфейса. |
| `features` | Реализует самостоятельное намерение пользователя. |
| `entities` | Хранит предметные типы, серверное состояние и чистую доменную логику. |
| `shared` | Содержит код, не связанный с конкретной предметной областью. |
| `utils` | Содержит глобальную техническую инфраструктуру. |

### Направления импортов

| Кто импортирует | Разрешённые зависимости |
| --- | --- |
| `app` | `pages`, `layouts`, `widgets`, `features`, `entities`, `shared`, `utils` |
| `pages` | `layouts`, `widgets`, `features`, `entities`, `shared`, `utils` |
| `layouts` | `shared`, `utils` |
| `widgets` | `features`, `entities`, `shared`, `utils` |
| `features` | `entities`, `shared`, `utils` |
| `entities` | `shared`, `utils` |
| `shared` | `utils` |
| `utils` | не импортирует FSD-слои |

Импорты вверх по таблице и циклические зависимости запрещены.

### Правила импортов

- Внутри одного слайса разрешено импортировать его сегменты.
- Между слайсами используйте только корневой публичный API.
- Используйте alias `@/` для импорта из другого слайса или пути с двумя и более
  `../`. Для соседнего файла и соседнего сегмента текущего слайса оставляйте
  относительный путь `./` или `../`.
- Feature не импортирует другую feature. Их объединяют widget или page.
- Entity не импортирует widget, feature или page.
- Page не содержит реализации feature/widget и импортирует только их публичные
  компоненты.
- Глобальные технические модули — исключение: их можно использовать там, где
  это необходимо для роутинга, конфигурации, типизации или кэширования.

## Pages и layouts

Page — верхнеуровневая композиция маршрута. Она получает route-параметры,
передаёт их в widget или feature и не содержит запросов, валидации, mutation
или сложной разметки.

Layout — независимый от маршрута каркас страницы. Он содержит общую навигацию,
отступы или визуальную структуру и принимает контент через `<slot />`.

Если блок можно использовать без знания конкретного маршрута, он должен быть
widget, feature или layout, а не page.

---

## Widgets, features и entities

Выбирайте слой по ответственности, а не по числу компонентов.

### Features — действия пользователя

Feature отвечает на вопрос: «что пользователь может сделать?». Она содержит
валидацию, правила доступности, локальное состояние и действия, необходимые
для одного самостоятельного намерения.

Feature не импортирует другую feature. Несколько features объединяют widgets
или pages.

### Widgets — законченные блоки интерфейса

Widget отвечает на вопрос: «какой функциональный блок пользователь видит на
экране?». Он может объединять features, entities, состояния загрузки и
несколько собственных UI-компонентов, но не создаёт новое бизнес-действие.

Компоненты, нужные только одному widget для его отображения, остаются внутри
этого widget и не становятся отдельными features.

### Entities — данные и чистая доменная логика

Entity содержит предметные типы, API-функции, Vue Query-хуки и чистую логику,
которая не зависит от экранной компоновки. Сегмент `ui` в entity необязателен.

Mapper, используемый одним widget, хранится в `utils` этого widget. Общий
formatter без предметной логики живёт в `shared/utils`.

## Сегменты слайса

Создавайте только необходимые сегменты. Пустые директории не добавляются.

```text
<layer>/<slice>/
├── api/                    # API-функции и Vue Query-хуки, если нужны
├── constants/              # неизменяемые словари, списки и конфигурация
├── model/                  # Vue composables, состояние и ViewModel-логика
├── ui/                     # Vue-компоненты и CSS Modules
├── utils/                  # чистые функции, схемы, мапперы, форматтеры
└── index.ts                # публичный API слайса
```

- `ui` содержит отображение и обработчики, полученные из `model`. Запросы,
  правила доступности и подготовка данных выносятся из компонента.
- `utils` содержит чистые функции без реактивного состояния: мапперы,
  форматтеры, схемы валидации и преобразования данных.
- `constants` содержит неизменяемые данные слайса: словари отображения,
  варианты контролов, breakpoints и статическую конфигурацию. Функции,
  фабрики, query-конфигурации и локальные результаты вычислений не относятся к
  constants, даже если объявлены через `const`.
- Корневой `src/utils` не содержит предметную логику. Здесь допустимы только
  глобальная конфигурация, логгер и инфраструктурные утилиты.
- Каждый непустой сегмент `ui`, `model`, `utils` и `constants` содержит свой
  `index.ts` для импортов между сегментами одного слайса.

### model — состояние и ViewModel-логика

`model` отвечает за состояние и поведение одного слайса, не зависящие от его
разметки. Для Vue это обычные composables с именем, начинающимся с `use`,
например `use-auction-view-model.ts`. В нём хранятся:

- реактивное состояние (`ref`, `reactive`);
- производные значения (`computed`);
- действия, валидация и предметные правила;
- локальные типы состояния и параметры, используемые только этим слайсом.

`model` не содержит Vue-компоненты, CSS, сетевой транспорт и вызовы API. Для
серверного состояния используйте Vue Query-хуки из `api/`; `model` может
использовать их публичный результат, если это необходимо для предметного
поведения слайса.

## API и Vue Query

Серверное состояние хранится и синхронизируется через Vue Query. Конкретный
HTTP-клиент проект не фиксирует: API-функции используют единый клиент,
выбранный при реализации.

```text
entities/<entity>/
├── api/
│   ├── endpoints/          # один файл — один HTTP-вызов
│   └── vue-query/          # один файл — один Vue Query query или mutation
├── constants/              # scope и неизменяемая конфигурация запросов
└── index.ts                # публичные query-хуки, ошибки и типы
```

- Каждый endpoint-файл выполняет один запрос, преобразует транспортную ошибку в ошибку
  приложения и не содержит Vue-кода.
- Каждый файл в `vue-query/` создаёт один query- или mutation-composable,
  вызывает endpoint и определяет инвалидации после изменения данных.
- Компонент не вызывает endpoint напрямую: он использует публичный
  Vue Query-composable слайса.
- Query-ключи одного предметного домена используют общий `scope`. Для
  инвалидации применяйте ключ scope, а не перечисление отдельных ключей в UI.
- Не создавайте локальные построители query-ключей в features, widgets или
  компонентах. Общая логика ключей живёт в `shared` или `utils`.

## Стилизация

- Используйте CSS Modules внутри SFC: добавляйте `<style module>` в тот же
  `.vue`-файл, что и компонент.
- Глобальный stylesheet содержит только reset, базовую типографику и правила,
  действительно общие для всего приложения.
- Не используйте глобальные классы для стилей конкретного компонента.
- Не используйте inline-стили, кроме runtime-зависимых значений.
- Не используйте `transition: all`; перечисляйте конкретные свойства.
- Для UI используйте согласованную UI-библиотеку и её систему иконок.

## Именование и публичный API

| Что | Стиль | Пример |
| --- | --- | --- |
| Папки, model-composables, utils, тесты | `kebab-case` | `use-resource-view-model.ts` |
| Vue-компоненты | PascalCase с расширением `.vue` | `ResourceList.vue` |
| Экспортируемые компоненты и типы | PascalCase | `ResourceList`, `ResourceSearch` |
| Model-composables | `use` + PascalCase | `useResourceViewModel` |
| Константы | `UPPER_SNAKE_CASE` для одиночных значений; camelCase для словарей и списков | `SCOPE`, `statusOptions` |

Каждый слайс раскрывает наружу только необходимое через корневой `index.ts`.
Внутренние компоненты, composables, utils и API-функции остаются приватными на
уровне корневого API.

UI-копирайт, документация и комментарии пишутся на русском языке. Не создавайте
коммиты от имени пользователя.
